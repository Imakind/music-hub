# Домашний стриминг: поиск без цензуры и рекомендации

Свой музыкальный сервис по мотивам видео: ищете любой трек, он скачивается
в домашнюю библиотеку (по возможности в версии без цензуры) и сразу играет.

```
 Телефон / браузер ──► Hub :8080 ──► Deezer API      (что за трек: каталог, обложки, дискографии)
   (PWA-плеер)          │       └──► YouTube Music   (где взять звук: yt-dlp)
                        ▼
                   ./music  ◄────── Navidrome :4533  (библиотека + Subsonic API для любых клиентов)
```

- **Hub** (`hub/`, Python + FastAPI) — «продавец пластинок»: поиск по каталогу,
  подбор источника, скачивание, теги, раздача файлов и веб-плеер.
- **Navidrome** — «полка»: хранит библиотеку и отдаёт её по Subsonic API
  (можно слушать через Tempo, Symfonium, Substreamer и др.).

## Запуск

### Через Docker (основной способ)

```powershell
docker compose up -d --build
```

- Плеер: http://localhost:8080
- Navidrome: http://localhost:4533 (при первом входе создайте админа; при
  желании впишите его в `.env` — см. `.env.example`)

### Без Docker (Windows)

```powershell
.\run-native.ps1
```

Запускается только Hub, без Navidrome; для плеера этого достаточно.

## Как устроен поиск без цензуры

`hub/app/sources.py` собирает кандидатов из трёх мест:

1. YouTube Music, раздел «песни» — официальные треки с флагом `isExplicit`;
2. YouTube Music, раздел «видео»;
3. обычный YouTube с запросом «… без цензуры» / «uncensored explicit»
   (если трек в каталоге помечен Explicit).

У каждого кандидата есть оценка:

| Признак | Баллы |
|---|---|
| Совпадение названия и исполнителя | до +60 |
| Длительность ±3 с / ±8 с / > 20 с | +30 / +15 / −50 |
| YT Music Explicit (для explicit-трека) | +25 |
| Пометка «без цензуры / uncensored» | +20 |
| Пометка «clean / radio edit / цензура» | −60 |
| slowed, sped up, cover, karaoke, Hz, live… | −35 |

Ни один признак не гарантирует, что слова на месте. Поэтому в плеере у
каждого трека есть меню **⋮** со списком кандидатов: можно открыть любой из
них на YouTube и перекачать трек из него.

Пока вы просматриваете список, Hub заранее подбирает источники для видимых
треков. Следующий трек в очереди скачивается, пока играет текущий.

## Файлы

Треки лежат в `music/Исполнитель/Альбом/NN - Название.m4a`. Теги (название,
исполнитель, альбом, номер, год, Explicit, обложка, Deezer ID) берутся из
каталога. Формат — m4a без перекодирования (AAC ~128 кбит/с, как на YouTube);
в `.env` можно переключить на `AUDIO_FORMAT=mp3`.

## API Hub

| Метод | Что делает |
|---|---|
| `GET /api/search?q=` | поиск по каталогу |
| `GET /api/artist/{id}`, `/api/album/{id}` | страницы артиста и альбома |
| `POST /api/tracks/{id}/fetch` | скачать трек |
| `GET /api/tracks/{id}` | статус |
| `GET /api/tracks/{id}/candidates?refresh=1` | кандидаты-источники |
| `POST /api/tracks/{id}/source` `{"video_id": "..."}` | перекачать из выбранного |
| `GET /api/stream/{id}` | аудио (поддерживает Range) |
| `GET /api/library` | скачанное |
| `POST /api/prefetch` `{"ids": [...]}` | заранее подобрать источники |
| `POST /api/events` `{"track_id", "type", "wave"?}` | действие: play, complete, skip, like, unlike, dislike, undislike |
| `GET /api/mix/daily`, `POST /api/mix/daily/rebuild` | Микс дня |
| `POST /api/wave/start` `{"track_id"?, "artist_id"?}` | запустить волну |
| `GET /api/wave/{id}/next?n=3` | следующие треки волны |
| `GET /api/profile` | сводка профиля вкуса |

## Важно

Скачивание с YouTube нарушает его условия использования, а распространение
скачанного может нарушать авторские права. Сервис рассчитан на личное
использование.

## Рекомендации (этап 2)

Пользователей у домашнего сервиса слишком мало для коллаборативной
фильтрации. Поэтому кандидатов предлагает внешний каталог (у Deezer —
«радио» исполнителя, похожие артисты, новые релизы), а мы оцениваем, насколько
каждый подходит под наш вкус, и собираем итоговый список сами.

**Звук → вектор** ([embedder.py](hub/app/embedder.py)). Готовая модель CLAP
`laion/larger_clap_music` превращает 30-секундное превью из каталога в 512 чисел.
Похожее звучание даёт близкие векторы, похожесть меряется косинусом. Скачивать
трек целиком не нужно, поэтому оценивается и музыка вне библиотеки. Работает на
видеокарте, если есть CUDA, иначе на процессоре. Без torch и transformers
рекомендации опираются только на сигналы каталога.

**Профиль вкуса** ([taste.py](hub/app/taste.py)):

| Действие | Вес |
|---|---|
| дослушал | +2 (повторы с убывающим эффектом: 2·log2(1+n)) |
| лайк ♥ | +1 |
| пропуск в первые 30 с | −1 |
| «не нравится» ✕ | −5, трек исключается |

Старые действия теряют вес по мере новой активности. Любимые треки
делятся на до 5 групп (сферический k-means), чтобы рэп, рок и метал не
усреднялись в кашу. Кандидат сравнивается с ближайшей группой. Сходство с
нелюбимым снижает оценку.

**Микс дня** ([recommender.py](hub/app/recommender.py)) — 50 треков, собирается
каждое утро (`MIX_HOUR`) или по кнопке.
- Кандидаты: любимые и давно забытые треки, «радио» и похожие артисты от любимых
  исполнителей, релизы последних 60 дней.
- Отсев: дубли, ремиксы, live и прочие нежелательные версии, дизлайки,
  прослушанное за 48 часов.
- Пропорция: 40% знакомого и 60% нового.
- Порядок: соседние треки похожи по звучанию, один исполнитель не идёт подряд.
- Треки скачиваются, а для Navidrome пишется `music/Playlists/Микс дня.m3u`.

**Моя волна** — бесконечный поток от вашего вкуса, трека (кнопка 〰 в плеере)
или исполнителя.
- Ранний пропуск штрафует исполнителя и похожие по звуку треки, но только в
  этой сессии. Штраф затухает с каждым следующим действием, так что случайный
  пропуск не становится запретом.
- Дослушивание и лайк тянут подбор в эту сторону и подгружают кандидатов от
  этого исполнителя.

## Удалённый доступ (Cloudflare Tunnel)

Сервис работает на вашем компьютере, поэтому для доступа с телефона вне дома
нужен внешний адрес. Cloudflare Tunnel даёт его без открытых портов и белого IP:
`cloudflared` сам подключается к Cloudflare, а запросы приходят по этому соединению.
Адрес виден всем, поэтому **вход по паролю обязателен**.

**1. Пароль.** В `.env` (скопируйте из `.env.example`) задайте длинный `HUB_PASSWORD`
и перезапустите Hub. Все страницы и API закроются формой входа; cookie живёт
30 дней, после 5 неверных попыток вход блокируется на 15 минут.

**2а. Быстро, без аккаунта** (временный адрес, меняется при каждом запуске):

```powershell
winget install Cloudflare.cloudflared
.\run-tunnel.ps1
```

В выводе будет адрес `https://….trycloudflare.com`. Откройте его на телефоне,
введите пароль и добавьте на главный экран (на iPhone: «Поделиться → На экран
„Домой“»).

**2б. Постоянный адрес** (нужны аккаунт Cloudflare и свой домен):
в панели Cloudflare Zero Trust создайте туннель, укажите ему сервис
`http://hub:8080` и скопируйте токен в `CLOUDFLARE_TUNNEL_TOKEN` в `.env`.

```powershell
docker compose --profile tunnel up -d
```

Navidrome (порт 4533) через туннель не публикуется. Если нужен доступ и к нему,
добавьте вторую запись в туннель и включите у Navidrome собственную защиту.

Cloudflare проксирует весь трафик, включая аудио. Бесплатный тариф для
личного стриминга обычно подходит, но его условия лучше прочитать.

## Свой сервер: работает без вашего компьютера

Туннель из прошлого раздела держится на домашнем компьютере. Чтобы плеер, библиотека
и рекомендации работали всегда, их можно поселить на сервере (AWS или Oracle Cloud),
а домашнему компьютеру оставить только то, что с сервера делать нельзя.

```
 Телефон ──https──► Сервер Oracle (круглосуточно)           Домашний ПК (когда включён)
                     Hub: плеер, библиотека, профиль,  ◄───  run-worker.ps1:
                     Микс дня, Моя волна, файлы              качает треки с YouTube,
                     Caddy: HTTPS                            считает звук на видеокарте
                                          очередь задач ───►  и загружает результат
```

YouTube часто блокирует скачивание с серверов дата-центров, а видеокарты у бесплатного
сервера нет. Поэтому задачи «скачать трек», «подобрать источник» и «посчитать вектор
звучания» выполняет домашний воркер (`hub/app/worker.py`), забирая их у сервера по токену.
Всё скачанное лежит на сервере и играет, даже когда компьютер выключен. Новые треки ждут в
очереди, пока компьютер не включится, а плеер показывает «Домашний компьютер: выключен».
Ограничение: поиск нового трека и свежий Микс дня при выключенном компьютере
завершатся не полностью.

### Вариант AWS (EC2)

Шаблон CloudFormation [aws/stack.yaml](aws/stack.yaml) создаёт всё сразу: сервер EC2
на ARM (Ubuntu 24.04, по умолчанию `t4g.small`, 40 ГБ диска), постоянный Elastic IP,
Security Group (22 только с вашего IP, 80/443 для всех) и ставит Docker. Диск
не удаляется вместе со стеком, музыка переживёт его пересоздание.
Ориентировочная цена `t4g.small` около 12–15 долларов в месяц плюс диск и трафик, проверьте
актуальные цены и бесплатные кредиты своего аккаунта.

1. В консоли AWS создайте пару ключей: **EC2 → Key Pairs → Create** (формат `.pem`).
2. **CloudFormation → Create stack → Upload a template file** → `aws/stack.yaml`.
   Параметры: `KeyName` (ваш ключ), `AllowedSshCidr` (ваш IP вида `x.x.x.x/32`).
   Через AWS CLI то же самое:
   ```powershell
   aws cloudformation deploy --template-file aws/stack.yaml --stack-name music-hub `
     --parameter-overrides KeyName=ИМЯ_КЛЮЧА AllowedSshCidr=ВАШ_IP/32
   ```
3. Подождите 3–5 минут, откройте вкладку **Outputs** стека: там `Domain` (впишите в
   `DOMAIN` файла `server.env`) и готовая команда загрузки `UploadCommand`.
4. Дальше как в шагах 3 и 4 ниже («Загрузка проекта» и «Домашний воркер»); в Ubuntu на AWS
   iptables настраивать не нужно.

Если подключите коннектор **AWS MCP**, шаги 2–3 может выполнить Claude прямо из сессии.

### 1. Сервер в Oracle Cloud (делаете вы)

1. Зарегистрируйтесь на cloud.oracle.com, тариф Always Free. Нужна банковская карта для
   проверки (списаний нет). Домашний регион выбирайте внимательно, потом его не сменить.
2. **Compute → Instances → Create instance:**
   - Image: **Ubuntu 24.04 (aarch64)**;
   - Shape: **VM.Standard.A1.Flex**, 2 OCPU, 12 ГБ памяти (бесплатный лимит — до 4 OCPU и 24 ГБ);
   - Boot volume: 100 ГБ или больше (бесплатно до 200 ГБ);
   - SSH keys: «Generate a key pair» и **сохраните приватный ключ** (`.key`).
   Если пишет `Out of capacity`, попробуйте другой Availability Domain или повторите позже.
3. **Сеть:** откройте инстанс → подсеть → Security List → **Add Ingress Rule**:
   Source `0.0.0.0/0`, TCP, порты `80` и `443` (две записи или `80,443`).
4. Запомните публичный IP инстанса.

### 2. Подготовка сервера (только для Oracle; на AWS уже сделано шаблоном)

```powershell
ssh -i C:\путь\ssh-key.key ubuntu@IP_СЕРВЕРА
```

На сервере:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu
# в образах Oracle системный firewall закрывает всё, кроме SSH
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save
exit
```

### 3. Загрузка проекта

В `server.env` (создан рядом с проектом) впишите `DOMAIN`. Без своего домена подойдёт
IP через sslip.io: для `203.0.113.7` это `203-0-113-7.sslip.io`. Пароль и токен уже заполнены.

```powershell
.\upload-server.ps1 -Server ubuntu@IP_СЕРВЕРА -Key C:\путь\ssh-key.key -WithLibrary
```

`-WithLibrary` переносит и уже скачанную музыку с историей прослушивания. Без него
сервер начнёт с пустой библиотеки. Затем на сервере:

```bash
cd ~/player && docker compose -f docker-compose.server.yml up -d --build
```

Первая сборка занимает несколько минут. Через минуту адрес `https://ВАШ_DOMAIN`
откроется в браузере и спросит пароль (он в `HUB_PASSWORD`).

### 4. Домашний воркер

В `.env` на компьютере впишите `SERVER_URL=https://ВАШ_DOMAIN` (`WORKER_TOKEN` уже есть).

```powershell
.\run-worker.ps1
```

В плеере на главной появится «Домашний компьютер: на связи». Для автозапуска при входе в Windows:

```powershell
$a = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-WindowStyle Hidden -ExecutionPolicy Bypass -File `"$PWD\run-worker.ps1`""
Register-ScheduledTask -TaskName "MusicWorker" -Action $a -Trigger (New-ScheduledTaskTrigger -AtLogOn)
```

### Кэш и предзагрузка

Чтобы не качать всё вручную и не ждать на каждом треке:

- **Окно вперёд.** Когда трек начинает играть, плеер просит скачать **5 следующих**
  треков очереди. «Моя волна» сама подгружает новые треки так, чтобы этот запас был всегда.
- **Приоритеты в очереди воркера:** трек, который нажали, идёт первым (0), затем
  следующие в очереди (1), затем фоновый прогрев Микса дня (2), в конце — анализ звучания (3).
  Если трек уже ждал в очереди, нажатие на него поднимает его вперёд.
- **Фоновый прогрев микса.** Пока домашний компьютер на связи, сервер каждые 90 секунд
  докачивает недостающие треки сегодняшнего микса, по 8 штук, с не более чем 3 попытками на трек.
- **Повторы.** Если YouTube ответил 403, воркер пробует следующий источник из списка.
- **Перезапуск воркера** (компьютер уснул, перезагрузился) сразу возвращает его
  незавершённые задачи в очередь.
- **«Моя музыка» и кэш разделены.** Заранее скачанное, но не прослушанное — кэш: он не
  попадает в «Мою музыку» и не влияет на профиль вкуса. После прослушивания, лайка или
  «Скачать альбом» трек переходит в «Мою музыку» насовсем. Кэш удаляется сам через
  `CACHE_DAYS` (7) дней или раньше, если он больше `CACHE_MAX_GB` (10 ГБ); сегодняшний микс
  не удаляется.

Скорость на практике: скачивание трека дома 12–30 с, загрузка на сервер 3–15 с. Ждать
приходится только первый трек; остальные успевают, пока играет текущий. Для yt-dlp
на домашнем компьютере стоит установить Deno (`winget install DenoLand.Deno`):
с ним YouTube реже отвечает 403.

### Обновление и обслуживание

- Новая версия кода: снова `.\upload-server.ps1 ...` (без `-WithLibrary`), затем на сервере
  `docker compose -f docker-compose.server.yml up -d --build`.
- Данные сервера лежат в `~/player/music` и `~/player/data` — это нужно бэкапить.
- Домашний ПК и сервер используют один `WORKER_TOKEN`. Утечка токена даёт возможность
  загружать файлы на сервер, поэтому при подозрении замените его в обоих `.env`.
